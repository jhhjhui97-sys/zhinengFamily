# Windows 商品与场景操作修复设计

用户要求现有离线版商品可编辑、删除，新建商品立即进入工作台，场景家具可删除，导入 GLB 能创建新商品。此前已授权代理自行选择可行方案；继续在专用 checkout 的 codex/windows-sales-controls 分支小步测试实施。

## 商品生命周期

商品列表每行提供查看、编辑、删除，详情提供删除当前商品。删除以 v8 deleted_at 标记移出有效列表和目录，保存的模型文件、场景版本、报价与订单不变。SKU 继续保留，删除操作使用 base_revision 防止过期删除。LocalProduct(id) 保持可供历史引用读取，编辑和附加模型拒绝已删除商品。数据库升级前备份，事务升级，已存在 deleted_at 的模拟降级库不重复加列。

## 实时目录与场景

catalog 返回所有有效商品，不要求先有 GLB。未上传模型的商品用毫米尺寸盒在本机显示，明确标注尺寸模型；导入/生成模型后显示商品模型。商品创建、更新、删除和附加资产成功后调用工作台刷新，返回设计页再次刷新。已有草稿及历史不因商品变化被重写。场景“删除当前家具”只删除选择的实例并保持其他对象，明确提醒保存新版本；保存和恢复保留旧版本。

## 模型导入并新建

新增“导入模型并新建商品”：填写分类、品牌、名称、SKU、价格、毫米尺寸及属性并选择 GLB 后，一次操作创建商品和资产。现有“导入当前商品 3D 模型”保留替换已有商品用途。

POST /api/model-files 复用流式 GLB 校验与 SHA-256 存储，返回 status/data {sha256,byte_count}，不创建商品。随后调用 product_create_model，携带商品字段和这两个值；C# 在单一 SQLite 事务中创建商品与资产、附加目录引用。损坏模型、重复 SKU、无效资料、SQL 失败不能留下半创建商品。本机授权、30 MiB 模型上限、上传超时和外部资源限制沿用现有服务。没有新增依赖。

## 验证

核心测试覆盖删除过滤、过期修订、跨工作区、历史数据与模型保留、v7 升级及原子模型商品创建回滚。纯逻辑测试覆盖删除实例不改源对象。Windows 浏览器覆盖列表编辑/删除、新建无模型商品立即出现并显示、GLB 新建商品及失败无部分数据、删除家具保存并恢复。全套 Windows CI 打包、真实 SQLite、Edge 回归通过后提供新版便携包。
