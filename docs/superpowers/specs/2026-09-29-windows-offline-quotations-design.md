# Windows 离线方案报价设计

## 目的与边界

用户要在同一台 Windows 电脑上完成客户→项目→真实商品场景→向客户展示价格的主要销售链路。已完成的本机客户、项目、在售 SKU、GLB 模型和不可变场景版本是依据；本阶段增加**可追溯的报价快照**。报价不是订单或收款凭证，不推断税率、运费或安装费。用户没有要求联网，继续使用 Edge 窗口、Node 回环服务、C# 桥接和 SQLite，资料保存在 `%LOCALAPPDATA%\ZhinengFamily`。

## 方案选择

1. 浏览器临时计算并打印：实现快，但商品改价或场景更新后旧报价不可复查；拒绝。
2. 仅保存总价：无法解释数量和单价，不利于门店核对；拒绝。
3. **从已保存的场景版本生成不可变的报价快照**：每件在售商品固定名称、SKU、数量、当时单价与小计，并固定客户、项目、场景版本和总金额。以后编辑商品、恢复场景或更换模型都不会改写已出报价；推荐。

## 数据与金额规则

SQLite v5 新增 `local_quotations` 与 `local_quotation_lines`，均带 `workspace_id`，报价关联本工作区客户、项目、场景和具体场景版本。每个报价有独立 UUID、创建人、本机创建时间、货币 CNY、整数分表示的总价和用于显示的十进制金额。明细按 `product_id` 聚合家具实例数量，保留商品名称、SKU、单价（整数分及规范字符串）、数量、小计；场景中的演示模型单独记录为未计价排除项，不能隐式计入总额。至少一件真实在售商品才能生成报价。价格用 C# `decimal` 或整数分计算；JavaScript 只格式化字符串，不用浮点计算金额。

创建请求只接收 `customer_id`、`project_id`、`document_id`、`scene_version`。服务端在单个 SQLite 事务中验证客户→项目→方案→场景版本的所有归属、读取当时商品价格并写入完整快照。客户端不能提交 `workspace_id`、`created_by`、价格、总额或明细来覆写结果。唯一约束和外键阻止跨工作区/跨项目伪造。引用不存在、未保存或跨范围场景拒绝；场景版本在并发编辑中不可变，报价依据明确。失败必须完全回滚。报价本阶段无修改或删除入口，后续如需调整创建新报价，不覆盖历史。

## 页面与输出

在已保存的项目方案旁提供“生成报价”；若场景有未保存修改则禁止生成并提醒先保存，避免看到报价与当前画面不一致。显示报价明细、排除的演示家具、总价、客户、项目、方案版本与生成时间。允许打印为纸质/PDF（调用本地浏览器打印，不需要外部服务），打印版不得包含编辑控件或技术字段。项目下可查看历史报价，不把后续改价反映到旧报价。加载失败、重复提交、冲突和不存在用中文安全提示。

## 验证与交付

真实 SQLite 测试涵盖 v1-v4→v5 升级、备份与失败回滚、金额精度、数量合并、旧报价快照不变、演示家具不计价、跨工作区/客户/项目/场景访问失败及并发创建。真实 Edge 测试走客户→项目→在售商品→场景保存→生成报价→改价后旧报价仍不变→打印视图→重启仍能读取。保留现有完整离线核心和 57 项 Windows 客户端测试，重新打包、独立审查并等当前提交对应 GitHub Actions。新阶段单独 draft PR，基于 `codex/windows-sku-models`，不合并级联 PR。
