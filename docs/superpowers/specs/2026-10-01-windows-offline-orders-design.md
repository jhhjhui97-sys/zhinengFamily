# Windows 本机订单设计（2026-10-01）

## 目的与边界

门店销售员在 Windows 本机、无网络条件下，从已保存的项目报价生成销售订单，查看/打印订单，确认或取消，并在重启后继续读取。沿用当前客户 → 项目 → 场景版本 → 报价的本地工作流。订单不是支付、库存锁定、税务发票或线上同步凭证；界面须明确提示这些边界。内置演示家具继续作为不计价排除项，不能单独生成报价或订单。真实外观依赖门店自行提供授权 GLB。

## 方案选择

订单只能由一份已存在且属于同一工作区、客户和项目的报价创建。服务端一次性复制报价的客户、项目、方案版本、商品名称、SKU、单价、数量、小计、总价及未计价演示项；浏览器只提交报价 ID 和作用域，不得提交金额、创建人或订单编号。每份报价最多生成一张订单，重复点击或并发调用返回同一订单，以避免重复销售单。新报价可另生成新订单，旧订单不受商品改价、场景恢复或报价列表变化影响。

SQLite v6 新增不可变 `local_orders` 头、`local_order_lines` 商品快照、`local_order_exclusions` 演示项快照，以及 `local_order_state` 当前状态和不可变 `local_order_events` 状态历史。均含 `workspace_id`，订单与报价使用复合外键绑定本工作区和项目。订单创建和所有明细、初始 `draft` 状态在一笔事务内完成。迁移先生成不覆盖的 `pre-v6` 备份，整次升级/回退失败不改变旧数据。`local_orders`/行项目/排除项一经创建禁止 UPDATE/DELETE；状态变更只更新 `local_order_state` 并追加事件。

状态为 `draft`（草稿）、`confirmed`（已确认）、`cancelled`（已取消）。允许 `draft → confirmed`、`draft → cancelled`、`confirmed → cancelled`，取消后不可恢复；重复设置当前状态返回当前订单，其他逆转返回 409。变更必须带 `base_revision`，在数据库事务内检查并以条件 UPDATE 防并发覆盖，事件与当前状态原子提交。确认和取消需页面明确确认，不能由客户端伪造操作者。

## 本机接口与页面

C# `LocalSceneStore` 提供 `CreateOrder(customerId,projectId,quotationId)`、`Order(id)`、`Orders(projectId,limit,offset)`、`SetOrderStatus(id,baseRevision,status)`；桥接白名单增加 `order_create`、`order`、`orders`、`order_status`，所有读取按本机工作区和当前客户/项目校验。无远端 JWT，仍使用 127.0.0.1 服务的同源/Cookie 防护。中文错误映射覆盖 404、409、422、503，响应不暴露 SQLite 异常。

设计工作台的报价明细加入“由此报价创建订单”，项目侧展示每页 20 张订单及状态；订单详情显示来源报价、客户、项目、方案版本、商品行、未计价演示项、总额、状态与状态历史。草稿可确认或取消，确认可取消；订单页面可打印/存为 PDF，打印区不含编辑控件或技术 ID。操作中禁用重复提交，切换项目或加载失败时不继续展示可打印的旧订单。

## 验收与证据

真实 SQLite 回归：v5→v6 备份和恢复、迁移失败回滚、只从报价创建、订单快照不随商品/场景变化、跨工作区/项目/客户隔离、客户端伪造金额拒绝、失败事务无半张订单、独立连接并发/重复创建只有一张、状态条件更新与历史原子性。真实 Edge 与便携包：客户 → 项目 → SKU 模型场景 → 报价 → 订单 → 确认 → 打印/PDF → 重启仍能读取，保留原有全部 59 项客户端和核心测试。独立审查后创建叠在报价分支上的 draft PR，等待该 SHA 的 GitHub Actions；不自动合并级联 PR。
