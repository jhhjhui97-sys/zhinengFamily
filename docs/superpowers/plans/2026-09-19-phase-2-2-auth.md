# Phase 2-2 Authentication Implementation Plan

**Goal:** Real FastAPI login via a Next.js BFF, server-held JWT cookie, protected admin pages, and a shared API client.

**Architecture:** Browser posts credentials to same-origin route handlers. The Next server calls FastAPI, stores the JWT in an HttpOnly cookie, validates it through `/auth/me` for every protected server render, and clears it on logout or upstream 401. `lib/api` centralizes upstream URL, JSON, bearer header, timeout, and safe Chinese errors. No browser storage or backend CORS change.

**Scope:** Only Phase 2-2 on `codex/phase-2-admin-scene`; no CRUD, SceneModel persistence, or PR.

1. Write Playwright tests for success, failure, route protection, refresh, logout, expired token, storage absence, and API error mapping. Run them red. Use mock upstream FastAPI for deterministic cases.
2. Implement `lib/api/{config,errors,server,auth,types}.ts`, BFF route handlers at `/api/auth/{login,me,logout}`, server layout guard, login form, and real user header. Run the new tests green; commit a cohesive authentication slice.
3. Update `.env.example` and README for server-only `API_BASE_URL`, run `npm test`, lint, typecheck, build, and inspect diff/secrets. Attempt real FastAPI/database login; report any environment limitation separately. Commit docs and push the existing branch; check Actions without creating a PR.

**Edge cases:** Missing cookie redirects; upstream 401 clears cookie; wrong credentials retain Chinese feedback; malformed upstream JSON and network timeout return safe 5xx feedback; arbitrary cross-origin POST cannot mutate an authenticated session.
