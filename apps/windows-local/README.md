# Windows 本地设计工作室

这是可以在 Windows 10/11 本机运行的**离线客户、项目、商品、3D 场景、报价和订单体验版**。双击便携包中的 `智能家居.exe`，独立 Edge 窗口会自动打开；不需要 Mac、Unity、Node、Python、PostgreSQL 或外部服务器。运行机器需要 Microsoft Edge 与 .NET Framework 4.8。资料在 `%LOCALAPPDATA%\ZhinengFamily\scenes.sqlite`，请定期备份整个目录；升级便携包时保留该目录。便携目录可放在任意本地磁盘，路径中有空格和中文也可启动。

操作：填写并保存客户 → 填写并保存该客户的设计项目 → 新建项目方案 → 载入两室一厅或导入 DXF → 从家具目录选择商品及房间放入场景 → 点击选中家具，中键按住拖动在地面平面移动、Shift + 中键按住拖动上下升降、右键按住拖动旋转 → 保存 v1/v2 → 查看版本 → 恢复旧版生成新版本。右侧可直接输入 X、Y、离地高度（mm）与旋转角度。默认在距墙面或家具面 50 mm 内自动贴合，可取消勾选或按住 Alt 暂时关闭；平行侧面可贴合，顶面可叠放，按商品真实尺寸检查并拒绝实体穿透、房间越界和超过层高。视图左键拖动与滚轮仍用于观察，移动时提示离最近墙面距离。客户和项目可重新选择、编辑；误建客户可“移出客户”，关联资料暂时隐藏，在“已移出客户”中恢复。旧版已保存但尚未关联项目的场景保留在“旧方案入口”，不会自动归到某个客户。支持只读历史 JSON、高级场景 JSON 校验和导出真实渲染 PNG。冲突返回中文提示并保留未保存内容。场景使用原有 SceneModel 全量校验和 SQLite 不可变版本，C# 桥接在本机运行。Node 服务只监听 `127.0.0.1` 随软件启动，退出窗口后由启动器关闭。浏览器没有 FastAPI JWT，也不连接远端 API；端口是临时分配的。

DXF 户型导入：在已选客户项目的方案中点“导入 DXF 户型”，选择不超过 8 MiB 的二维文本 `.dxf`，核对房间轮廓图层及可选墙体中心线图层。图纸标注毫米、厘米或米时会给出换算建议，仍需人工确认；单位不明时点预览中的已知长度直线，输入实际毫米长度完成校准。点“生成 3D 草稿”后检查空间，再手动保存新版本。首版仅转换 LINE、直线 LWPOLYLINE/POLYLINE 与闭合房间轮廓；不自动识别门窗、水电、梁柱，也不支持 DWG/PDF、曲线和块内对象。为保证界面流畅，单个房间轮廓最多 1000 顶点，一次导入最多 100 个房间、5000 个房间顶点和 5000 段墙线；超限图纸须先简化。墙厚默认 200 mm、层高默认 2800 mm，均为估算值，施工前务必核对原图。无闭合房间轮廓的图纸需先整理。原始 DXF 按 SHA-256 存于 `%LOCALAPPDATA%\ZhinengFamily\floorplans`，请连同整个资料目录备份。

真实本机画面：[客户项目中的 3D 场景](../../docs/images/windows-offline-sales-room.png)。左侧的客户和项目表单可折叠；左、中、右栏在桌面宽度下独立滚动，查看项目时场景始终留在视野中。

首次打开旧版 `scenes.sqlite` 时，软件会先用 SQLite 在线备份生成不覆盖的 迁移前备份，再在事务中升级客户、项目、场景、商品、模型和报价表；失败会回滚，原数据仍可恢复。升级前仍建议自行复制整个 `%LOCALAPPDATA%\ZhinengFamily` 目录。离线客户/项目/商品资料与在线后台的账号或 PostgreSQL 数据**不会自动同步**。

内置四款 Khronos glTF 示例模型：复古三人沙发、织物单人椅、丝绒沙发和商用冰箱，含真实纹理与材质；物理光照、阴影与场景中毫米尺寸放缩均使用本地资源。房间木地板也使用离线 PBR 贴图，浅色墙面使用法线和粗糙度贴图；贴图缺失时会明确提示，仅缺失贴图的表面回退到基础材质。模型与材质创作者、许可和文件哈希见 [第三方素材清单](ASSET-LICENSES.md)。这些是演示商品和环境，不代表商家实际库存或指定铺装。[这张图](../../docs/images/windows-offline-room-materials.png)来自实际 Edge 离线客户端，不是 AI 生成的效果概念图。

商品管理：点顶部“商品管理”，录入分类、品牌、名称、SKU、价格、毫米尺寸及可选 JSON 属性。每行有“查看”“编辑”“删除”；删除商品将其移出在售列表，旧场景、模型、报价和订单仍保留，SKU 继续保留。可按名称/SKU/品牌搜索、分类筛选并每页查看 20 条；修改过期时提示冲突并保留表单。价格按原始十进制字符串显示，不经浮点重新计算。保存、编辑、删除或导入模型后，设计工作台目录立即刷新。没有 GLB 的在售商品以真实毫米尺寸的尺寸盒显示，可摆放、保存及报价。

导入模型：填写新商品资料并选择获授权的自包含 `.glb` 文件（最大 30 MiB），点“新建在售商品”或“导入模型并新建商品”，都会一起保存新商品及模型；普通新建未选文件时创建尺寸商品。非法文件、资料校验失败或 SKU 重复不会产生半成品商品。点“导入当前商品 3D 模型”则替换已选商品的当前模型，须先保存该商品的资料修改。可离线加载多网格、嵌入贴图以及受支持的 Draco、Meshopt、KTX2 压缩资源；不支持的必需扩展或没有可显示网格的文件会明确提示。也可上传商品正面 PNG/JPEG 图片（最大 5 MiB），按已保存的宽、深、高在本机生成尺寸近似 GLB。沙发、床、桌使用简化外形，其他商品使用尺寸盒，图片贴于正面；单张图片无法还原真实背面或材质。已经摆入场景的尺寸实例，可选中后点“使用商品当前模型”切换到该商品已保存的 GLB，保留实例尺寸、位置和角度，再保存新版本。场景版本固定已有模型的资产 ID，后来替换模型不会改变旧版场景；尺寸模型的场景实例同样保留当时尺寸。模型文件和 SQLite 都在 `%LOCALAPPDATA%\ZhinengFamily`，备份时须复制整个目录。

删除已摆放家具：点击选中家具后，点“删除当前家具”。只从当前草稿移除该实例，确认效果后点“保存”；之前的场景版本仍可打开或恢复。

墙面与地面装修：在设计工作台展开“墙面与地面装修”，选房间及房间地面、整房墙面或朝向该房间的单面墙。墙面与地面各有 21 个选项（含自定义），覆盖涂料、壁纸壁布、瓷砖、木饰面、石材、微水泥、金属玻璃、木地板、弹性地材、地毯等常见做法；可自定义名称、分类、表面纹理、主辅色、规格、缝宽缝色、铺设方向、粗糙度、金属度和不透明度。支持直铺、错缝、人字、鱼骨、棋盘、篮编、六角等铺法，也可记录基层处理、饰面厚度、每层名称/厚度/说明和特殊工艺。点“应用装修到草稿”后保存新版本；“恢复默认表面”同样仅修改草稿，旧版本仍保留当时装修。单墙只改变当前房间朝向的一侧，缺少实体墙的边界提供装修示意，已有墙体保留门窗洞口。

真实本机商品页画面：[1024px 横屏商品管理](../../docs/images/windows-offline-products.png)。图中商品为自动化测试在真实本机 SQLite 创建的示例资料，产品页面、筛选、金额和详情均由实际 Edge 客户端渲染。

导入商品模型后的[实际场景画面](../../docs/images/windows-offline-sku-model.png)由 Edge 在真实本机 SQLite 上生成；前方为关联 SKU 的导入 GLB，后方为内置演示家具。

报价：在项目方案中摆放在售 SKU（GLB 或尺寸模型均可），保存场景版本后点“生成报价”。报价按本机当前商品单价生成一次性快照，保留当时的名称、SKU、单价、数量和总价；商品后来改价不会改变旧报价。内置演示家具不计价，纯演示场景不能生成报价。报价可以再次打开、打印或存为 PDF；这是商品参考价，不含运费、安装费和税费的最终约定。真实本机画面见[报价截图](../../docs/images/windows-offline-quotation.png)。

订单：打开已保存报价，点“由此报价创建订单”。同一份报价重复点击只会读取同一张订单；草稿可确认或取消，已确认订单仍可取消，状态历史保留。订单商品与金额独立快照，后续商品改价或场景恢复不改变旧单；可打印或存为 PDF。订单**不代表已付款或锁定库存**。真实本机画面见[订单截图](../../docs/images/windows-offline-order.png)。

当前限制：内置目录只有四款演示模型；图片生成的是尺寸近似模型，逼真商品模型仍需门店提供合法且画质合格的 GLB。当前直接导入入口为自包含 GLB 2.0，不代表支持 Windows 能打开的所有 3D 格式；GLTF 分离文件、FBX、OBJ 等需先转换。贴合与碰撞按商品尺寸包围盒计算，不识别模型内部空隙或真实接触形状。装修纹理为本地示意，镜面采用近似反射，实际颜色、质感和做法须核对材料样板；基层、厚度与工艺层次仅作记录，不改变房间净尺寸、家具高度，也不提供施工验算或装修材料报价。丰富灯具、支付、库存管理、自动 AI 布局和完整 CAD 编辑/VR 尚未实现。这是可用的本地客户→项目→场景和商品管理体验版，**不是完整门店交付系统**。Unity 6000.3.0f1 工程保留，但本机官方 Editor 下载重定向到返回 404 的节点，因此 Unity Editor/Player 未验收；Windows 版采用不依赖 Unity 许可的本地浏览器渲染。

开发构建：先运行 `npm ci --prefix apps/windows-local`，准备 Node24、Newtonsoft.Json 13.0.2 `net45` DLL 和对应许可证，再运行 `tools/package_windows_local.ps1`。该脚本拒绝覆盖已有输出目录。运行 `npm test --prefix apps/windows-local`、`npm run check --prefix apps/windows-local`、`npm run format:check --prefix apps/windows-local` 验证。证据见 [Windows 验证记录](../../docs/windows-local-verification.md)。
